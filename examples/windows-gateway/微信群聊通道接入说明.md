# 微信群聊通道接入说明

> 目标：把**微信（个人号）群聊**接入 Harness——群里 @小号，AI 自动应答，回复以“小号本人”身份发出。
> 技术路线：**aixed/WeChat-Hook（version.dll）** 微信 **4.1.10.27**（Windows 本机 hook + HTTP 30001）→ Windows 网关（Python `gateway.py`）→ Mac/云端 Harness（演示台 `8789 /api/incoming`，后续接入桥接）。
> ⚠️ **风险声明**：hook 属非官方协议，违反微信服务协议，**小号封号风险**；务必只用**微信小号**，勿用主号；切勿商用/营销。

---

## 一、整体架构

```
[Windows 你的电脑]
  微信 4.1.10.27（小号登录）+ version.dll → 本机 HTTP 30001（收消息靠轮询消息库；发消息 /SendTextMsg）
        │ gateway.py（Python：轮询新消息 → POST 给 Mac → 拿回复 → 发回群里）
        ▼ HTTP（局域网/公网，需认证）
[Mac 或 云服务器]  Harness（3080）+ 演示台 wechat-demo（8789，/api/incoming，agent 生成回复）
```

## 二、你要准备的东西（Windows 侧）
**Windows 上安装 DSH 的注意事项（2026-08-23 实测踩坑）**：
- 建议用**官方 npm 安装版**（`npm install -g @deepseek-ai/dsh` → `npx dsh web`），与 Mac 同构：设置页结构一致，我们的「连接」页/「外部打开」补丁可直接注入；
- 若用了**源码构建版**（设置页为“通用设置/模型/Agent 预设”，标题带 Local Build）→ “连接”模块不适用；模型配置失败（failed to fetch）请按《Windows修复指令-codex.md》处理；
- 模型 API Key：填 DeepSeek key + `https://api.deepseek.com` + **手写模型名**（勿依赖自动拉取目录）；保存后用 `npx dsh --profile headless "你好"` 验证。



| # | 事项 | 说明 |
|---|---|---|
| 1 | **微信小号** | 可接受封号的号；准备好扫码登录 |
| 2 | **微信 PC 4.1.10.27**（必须这个版本） | 你当前 4.1.12.26 不支持 → **必须降级**（见下） |
| 3 | **version.dll** | 从 [aixed/WeChat-Hook Releases](https://github.com/aixed/WeChat-Hook/releases) 下载 `v4.1.10.27` 资产 |

| 5 | Node ≥18（Mac 侧已有） | 跑演示台/harness |

## 三、Windows 侧部署步骤

1. **降级微信**（4.1.12.26 → 4.1.10.27）：
   - 下载 [WeChatWin_4.1.10.27.exe](https://github.com/aixed/WeChat-Hook/releases/download/v4.1.10.27/WeChatWin_4.1.10.27.exe) 并安装（覆盖当前版本即可，小号数据无所谓）；
   - 微信 → 设置 → 通用 → **关闭“自动升级”**（否则升级到 4.1.12.x 就失效）；
2. **放 DLL**：`version.dll` 放入微信安装目录 `C:\Program Files\Tencent\Weixin`；
3. **杀毒白名单**：Defender/杀软 → 白名单：微信目录 + `version.dll`（hook 必被误杀，不加白名单会加载失败）；
4. **登录小号** → 验证 hook 生效：浏览器打开 `http://127.0.0.1:30001/QueryDB/GetAllDBName`（有 JSON 返回=OK）；
5. **装网关**：把 `dsh-channel-im/examples/windows-gateway/` 拷到 Windows（或从私人仓库 clone）。

## 四、网关（Windows 侧）

```bash
pip install -r requirements.txt     # 无第三方依赖其实可省；纯标准库
python gateway.py
```

- 首次运行先改 `config.json`：
  ```json
  {
    "hook_host": "http://127.0.0.1:30001",
    "mac_url": "http://<Mac局域网IP>:8789",   // 改成你的 Mac IP（终端: ipconfig getifaddr en0）
    "room_policy": "at",                       // at=只回@我 all=全回 off=不回群
    "debug_discover": true                     // 首跑打印微信库/表结构
  }
  ```
- **首跑**：打印全部数据库/表 → 把“消息库/消息表”及字段名填进 `SCHEMA`（time/sender/content/self/群标记），`debug_discover` 改 `false`；
- 日志出现轮询即正常；`GetSelfProfile` 失败说明微信/hook 未就绪。

## 五、Mac/云端侧（Agent 大脑）

```bash
cd dsh-channel-im/examples/wechat-demo
# config.json：padlocalToken 可留空（本演示台在“外部通道模式”下仅用作 agent+UI）
node server.js        # → http://127.0.0.1:8789
```

- 浏览器打开 8789 看消息流（收到群里的@消息会实时显示、agent 回复后日志可见）；
- agent 模式：`echo`（回显）/ `openai` 兼容 / `custom`（对接 harness/正式桥接）；
- **接入正式 harness**：把 `customUrl` 指向 harness 会话桥（或未来桥接的 `/api/incoming`），消息进会话、回复出会话（实现阶段）。

## 六、联调顺序（首次跑通）

1. Windows：微信小号登录（hook 30001 OK）→ `python gateway.py`（首跑定 SCHEMA）；
2. Mac：`node server.js`（8789 起、浏览器可见）；
3. 微信小号所在群 → **@小号** 发一句话；
4. 看链路：网关日志（收到→转发）→ Mac 8789 消息流（收到→回复）→ 群里出现小号的回复。

## 七、常见问题

| 现象 | 排查 |
|---|---|
| 30001 无响应 | 微信版本非 4.1.10.27 / version.dll 没放对目录 / 被杀毒拦（看白名单） |
| 网关查不到库表 | `debug_discover` 输出结构后填 SCHEMA；字段名以实际为准 |
| 群里不回复 | `room_policy=at` 只回@我；确认“@”的是小号昵称 |
| 单聊不回 | 检查 `mac_url`、演示台是否在跑、agent 模式是否 echo |
| 回复没收到 | 看 Mac 8789 日志最后一步（回复是否生成、SendTextMsg 是否成功） |
| 机器人自聊/刷屏 | 确保 `selfUserId`/自环防护开启；回复频率由 minIntervalMs 控制 |

## 八、风险控制（务必遵守）

- 只用**小号**；不营销、不加人、不高频刷屏；
- 只开必要群（建议 `room_policy=at`）；
- 上线前加：敏感词/白名单（只允许指定群）、审计日志、人工兜底（紧急关停命令）。
